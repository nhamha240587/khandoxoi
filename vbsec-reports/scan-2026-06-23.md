### BROKEN-ACCESS-CONTROL — Bypass thanh toán hoàn toàn

**Mô tả ngắn:** Webhook xác nhận thanh toán chỉ kiểm tra API key *khi* biến `SEPAY_API_KEY` có giá trị. Nếu env này trống (hiện tại production đang trống — đã xác nhận qua test), toàn bộ bước xác thực bị bỏ qua, webhook mở hoàn toàn.

```typescript
const expectedKey = process.env.SEPAY_API_KEY || ''
if (expectedKey && apiKey !== expectedKey) {   // ⚠️ expectedKey rỗng → điều kiện false → KHÔNG chặn
  return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
}
```

**Tại sao nguy hiểm:** Đây là endpoint quyết định một đơn đã "thanh toán" hay chưa. Mở = ai cũng tự xác nhận đơn của mình mà không trả tiền.

**Hacker (hoặc khách gian) khai thác — chỉ 2 bước:**
1. Đặt đơn thật trên web → nhận lại `refCode` ngay trong response JSON (vd `KDX2333238579`).
2. Tự gửi: `POST /api/payment-webhook` với `{"content":"KDX2333238579","transferAmount":98000}`.
   → Đơn chuyển `paid` → POScake đẩy sang "Chờ chuyển hàng" → Telegram báo "✅ đã thanh toán".
3. Cô Hạ thấy "đã thanh toán" → gói hàng gửi đi. **Khách chưa trả đồng nào.**

**Code fix (fail-closed — chặn cả khi quên set env):**
```typescript
const expectedKey = process.env.SEPAY_API_KEY || ''
// Bắt buộc phải cấu hình key; thiếu key = từ chối, KHÔNG mở cửa
if (!expectedKey || apiKey !== expectedKey) {
  return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })
}
```
**Kèm theo:** set `SEPAY_API_KEY` trên Vercel = đúng giá trị API Key trong SePay dashboard (Cấu hình → Webhooks).

**Đọc thêm:** OWASP A01:2021 Broken Access Control; SePay webhook authentication docs.

### HTML Injection vào Telegram → mất thông báo đơn

**Mô tả:** Các hàm `notifyKdxPending` / `notifyKdxPaid` build tin nhắn với `parse_mode: 'HTML'`, nhưng nhúng trực tiếp dữ liệu khách nhập (`name`, `address`, `note`) — đều là L1 (untrusted) — mà không escape ký tự `<`, `>`, `&`.

**Tác động (kép):**
1. **Mất đơn (nghiêm trọng hơn):** Khách tên `"Anh < Lan"`, địa chỉ chứa `&`, hoặc note có `<3`... → Telegram API trả lỗi 400 (HTML không hợp lệ) → `sendMessage` thất bại âm thầm (fetch không bắt lỗi) → **Cô Hạ KHÔNG nhận được thông báo đơn đó.** Đơn bị bỏ sót.
2. **Giả mạo nội dung:** Khách cố tình nhập thẻ HTML để chèn chữ giả vào tin Telegram (vd giả "đã thanh toán").

**Code fix — escape trước khi nhúng:**
```typescript
function esc(s: string) {
  return String(s).replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')
}
// rồi dùng: ${esc(data.name)}, ${esc(data.address)}, ${esc(data.note)}
```

**Đọc thêm:** Telegram Bot API — HTML style; OWASP Output Encoding.
